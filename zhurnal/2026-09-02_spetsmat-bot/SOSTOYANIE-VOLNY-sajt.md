каждый её прогон переставляет РЕАЛЬНОГО ребёнка. На сейчас в базе два таких следа, оба от
проверок P1:

```
(3, Афанасьева,  Настя → закрыт 2026-09-03)   →  (58, Афанасьева,  Полина, открыт 2026-09-03)
(4, Белеванцева, Настя → закрыт 2026-09-03)   →  (59, Белеванцева, Полина, открыт 2026-09-03)
```

Свой собственный след (Агаркова) я уже убрал в 23:20. Эти два убираются ТЕМ ЖЕ способом и
ТОЛЬКО после того, как P1 завершится — иначе он поставит их заново:

```sql
delete from enrollment where id in (58,59);
update enrollment set valid_to='9999-12-31' where id in (3,4);
```

🔴 **Порядок обязателен:** сначала `delete`, потом `update`. Обратный даёт
`IntegrityError: enrollment intervals for one (student_id, weekday) must not overlap`.
Страницей это не откатывается: правка, сделанная сегодня, сегодня же дала бы интервал нулевой
длины, а схема требует `valid_from < valid_to`.

**Пока этот долг не закрыт, распределение владельцу показывать нельзя:** он увидит двух детей
у преподавателя, к которому их никто не переводил.
