Отчёт без адреса артефакта — это отчёт о работе, которую нельзя посмотреть.*

🔴 **НЕОБРАТИМОЕ — ОТДЕЛЬНЫМ СПИСКОМ, даже если оно стояло в задании.** Удаление, перезапись, переименование, перемещение, `git reset`/`checkout` поверх несохранённого, любая правка, вышедшая за зону, — каждое ОДНОЙ строкой: **что · где · чем восстанавливается** (хэш коммита, путь к бэкапу). **4 · ГАШЕНИЕ.** Невлитого не осталось: `git --no-optional-locks branch --no-merged main`.

поставь заявку `--rod git-operaciya` и назови число в отчёте. Команда для своей ветки:
`git --no-optional-locks log --oneline @{u}.. | wc -l` → 0.
Ненулевое на своей ветке означает, что работа существует только на этом диске.

**6 · ПРОВЕРКА ФАКТОМ, А НЕ ПАМЯТЬЮ.** Числа по каждому репозиторию — вне git · невлитых своих

   таблица и есть будущее. **Починено:** обе породы отсутствия складываются в одном месте.
2. **`snyato` было `len(ids)` — числом НАМЕРЕНИЙ**, тогда как цикл умеет пройти строку
   мимо. Сегодня мимо не проходит ни одна, и именно поэтому подмену нельзя было увидеть.
   **Починено:** считается сделанное; тест держит `snyato == (ДО − ПОСЛЕ) == len(id)`.
3. **Обе двери выбирали занятие голым `where held_on = ?`**, тогда как
   `SqliteSessions.for_day` отдельно документирует «SMALLEST id first», потому что
   `sessions.held_on` не уникален. Согласие держалось на порядке обхода rowid.
   **Починено:** `order by id`; тест ставит два занятия на одну дату.
4. **НЕ моё и НЕ починено — отметка присутствия из бота стирает ручную правку.**
   `bot/routers/text_input.py:582` зовёт `mark_attendance(..., PRESENT)` без `teacher_id`,
   а `infra/sessions_repo.py:133` пишет `update attendance set status = ?, teacher_id = ?`
   — то есть `NULL`. Ручная правка исчезает сама, как только преподаватель отметит ребёнка
   пришедшим. Проверено мной по коду отдельно от верификатора: вызов и вправду без
   `teacher_id`. Оба файла вне зоны — пункт 5 в `## ВОПРОСЫ`.

Верификатор отдельно проверил и снял два подозрения: удаление строки со статусом «был» не
теряет наблюдаемой отметки присутствия (везде в проде присутствие выводится как «не отмечен
отсутствующим»), а имена в `GET` без пароля не утечка — публичная половина сайта печатает
